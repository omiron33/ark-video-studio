# Ark Lyric Studio

Ark is a local, agent-directed lyric film engine. Its source of truth is a portable project JSON, not a flattened final video. The original Python v1–v3 engine is retained; the new engine lives in `engine/`.

## Run

Requires Node 22+ and FFmpeg/ffprobe. Dependencies are pinned in `package-lock.json`.

```sh
npm ci
npm run studio -- --project projects/genesis7/project.json
```

Open the printed loopback URL. Play the original audio, scrub, step individual frames, loop a section, change its treatment/accent/type size, save direction, and render a preview. The preview uses the same deterministic Canvas scene functions as the fast native Skia renderer. The server stays local and supports proper seeking/range delivery for audio and exported MP4s.

## Edit through an agent

Ask: “Make the waters rise more dramatically,” “replace only highest-ground with line art,” or “keep the lyric timing and completely redesign the last scene.” Agents inspect IDs, patch a section, render it, and evaluate the resulting video. The interface does not require an inference API or another paid video service.

```sh
node engine/cli.mjs inspect --project projects/genesis7/project.json --json
node engine/cli.mjs patch --project projects/genesis7/project.json \
  --section waters-rise --set '{"direction":{"accent":"#cf603c"}}'
node engine/cli.mjs render --project projects/genesis7/project.json \
  --section waters-rise --out output/one-section.mp4
```

A replacement JSON contains an entire scene, including its stable ID, start/end, style, word IDs, asset IDs, direction, and seed. `replace --section ID --file replacement.json` preserves its interval by default. `--retime` is explicit and changes neighboring edges. The validator refuses gaps, bad IDs, missing sources, incompatible word-role references, or unknown treatments. Successful edits write a recoverable revision backup. Timing stays in words, not in decorative animation keyframes.

Use `direction.scale`, `direction.accent`, the semantic `roles`, and treatment-specific settings for ordinary art-direction changes. Keep `assetIds` complete. If a transition borrows the next scene, its dependencies must be declared and tested. Keep each scene independently meaningful enough to preview alone.

## Visual vocabulary

- `rise`: the subject physically travels upward on its sung verb; supporting words establish above/below relationships.
- `terrain`: drawn contour lines and individually placed letters build a crest. Its optional portal carries the camera through the actual O counter in the ground word into the next photograph.
- `submerge`: words descend behind a moving water surface after their sung phrase. With GPT imagery it uses photographic depth, restrained rain and an alpha-matted foreground wave; graphic briefs use drawn water and the same occlusion behavior.
- `orbit`: words placed on a rotating circular path.
- `impact`: per-word percussive type with restrained depth and beat accents.
- `verse`: quiet phrase composition for an imported song's first draft.
- `story`: authored word rows, per-word font roles, photographic backdrops, semantic actions and procedural line motion. The finished [Genesis 4 project](../projects/genesis4-full/README.md) demonstrates the controls below.

For `style: "story"`, choose `direction.mode` by meaning:

| Mode | Supporting motion |
| --- | --- |
| `fracture` | Drawn cracks and tension lines for rupture, rejection or impact |
| `vortex` | Perspective tunnel geometry for pressure and confrontation |
| `scorch` | Heated line tracery for forge or destructive passages |
| `eclipse` | Intersecting circular forms and occlusion for judgment or protection |
| `lineage` | Branching connections for family succession and new life |
| `strings` | Plucked lines that respond to actual sung-word attacks |

`direction.kinetic` accepts `strike`, `split` or `cascade`, or an object such as `{ "mode": "strike", "amount": 0.8, "seconds": 0.17 }`. Entrances start at the canonical word onset and settle within 0.2 seconds; they never shift lyrics to invented beats. Longer semantic movement belongs in `direction.actions`, with an explicit trigger word and target IDs.

`direction.colorGrade: "red-black-white"` gives photographic backdrops a restrained crimson tint with neutral black shadows and preserved white highlights. It leaves the lyric layer unchanged. Pair it with an explicit `palette` and `direction.accent`. These controls are opt-in; existing films keep their original appearance.

Treatments are starting points. Extend `registerStyle` in `engine/visual.mjs` for a new scene language; keep frame evaluation pure and deterministic. The current compositions are art-directed for 16:9. Assets are never generated by a hidden third-party API. For new artwork use GPT Image, copy the selected image into the project, record its prompt/provenance, and reference its ID.

### Spatial and semantic choreography

`story` scenes can set `direction.choreography` to a registered treatment from `CHOREOGRAPHY_CATALOG` in `story-visual.mjs`. The 16 `camera-*` treatments project fixed world-space words and supporting geometry through the same camera. `camera-switchback`, `camera-rail`, `camera-canyon`, `camera-stairwell`, `camera-braid` and the other camera treatments follow phrase stations; they do not move the camera on every syllable. Optional `cameraGroups` contains arrays of word IDs for a continuous multi-phrase journey. Near camera planes fade before older text can obscure the current phrase. Instrumental camera scenes traverse geometry without inventing words.

Sixteen additional semantic treatments include `split-verdict`, `falling-weight`, `word-strike`, `echo-cry`, `incision`, `balance-offering`, `refusal-bar`, `fingerprint-mark`, `chain-lineage`, `branching-seed`, `string-pluck`, `forge-assembly`, `tally-vengeance`, `negative-space`, `threshold-exile` and `breath-resolve`. These change the word composition and behavior, not just its background. Photographic scenes retain their protected `textBox`.

Enable `creation.creativePolicy.choreography` with `{ "version": 1, "minDistinct": 30, "maxUses": 3, "noRepeatedTriples": true }` for long films. The gauntlet counts registered lyric treatments, rejects adjacent repetitions and repeated three-treatment sequences, and does not count picture IDs, fonts or random seeds as distinct animations. A preserved bespoke scene can use `direction.authoredTreatment: { "id": "...", "description": "..." }`. Structural variety still needs independent visual review; thirty names alone do not prove thirty compelling scenes. Historical projects remain opt-in.

The [Genesis 4 motion revision](../projects/genesis4-motion-v2/README.md) preserves its original canonical words, audio, measured beats and key photographs while revising direction. Readability and the music determine speed. Motion variety is not permission to make a restrained phrase frantic.

## Timing and speed

Future `create` runs also apply the [creative policy](CREATE.md#visual-rhythm-for-future-runs): unique scene artwork, measured accent bursts, restrained holds and slow supporting dissolves. `direction.pacing` is opt-in at render time, so older manifests retain their existing choreography. Factual artwork and timing audits accompany the gauntlet; visual judgment still determines whether the planned contrast succeeds on screen.

Words retain stable IDs, source intervals, confidence and correction provenance. Beat events are separate. A strong music accent can drive a camera or a wave without moving the sung-word onset. The selected Genesis clip initially used three local ASR cross-checks. The autonomous audio reviewer now checks waveform fidelity, lyric recognition and independent forced alignment, and can repair disputed word boundaries before rerendering. Machine review records its method, thresholds and evidence; it does not invent a subjective listening score.

A section cache fingerprints the scene, intersecting words (including boundary overlaps), direction, actual image/font bytes, relevant beats, renderer source and export profile. Portal transitions also fingerprint their successor. Ordinary edits only invalidate affected sections. A global renderer/font/profile change intentionally invalidates all dependent sections.

Chunks are validated and published atomically. FFmpeg copies compatible cached picture streams into the final file, then muxes the continuous source audio once. Draft `--scale .5` uses the same choreography at half resolution. Engine code edited while the server runs is loaded under a new revision; a render fails publication if its inputs change mid-render.

## Quality loop

```sh
node engine/cli.mjs render --project projects/genesis7/project.json --out output/film.mp4
node engine/cli.mjs gauntlet --project projects/genesis7/project.json \
  --video output/film.mp4 --out output/review
```

The gauntlet checks real decoded output, stream formats, frame count, timing and audio presence. It captures word-onset frames, transitions and contact sheets, and binds evidence to the video SHA and the source revision. It starts **pending**. Completion requires technical checks, measured audio/sync evidence, and five visual categories scored at least8/10 by the local model or an independent agent. Native OCR must recover every required lyric during its visibility window. The engine can finish as `machine_verified` with local reviews, or `independently_reviewed` with independent visual judgment plus measured audio. `review-check` rejects stale approvals after source, asset, evidence or video changes.

The engine owns listening and sync verification. A bound machine audio report can satisfy the sync gate through actual decoded-waveform and speech/forced-alignment evidence. A local vision model separately judges decoded scene sequences, proposes supported edits and sends changed sections through the render loop again. No human hearing approval is required. A failed or unavailable reviewer cannot manufacture a pass. A technically valid render does not mean a good film.

If a failed visual review proposes the existing scene unchanged, the engine asks once for an actionable alternative and records both proposals. Any actual edit must be rendered and reviewed again. An unchanged second proposal remains unresolved. An independent agent can inspect the encoded evidence, repair the scene, record its visual judgment through the gauntlet, and finalize the creation run only after the current audio and technical gates pass.

Iterate: render → inspect actual output → list concrete failures → change those scenes → render again → independently inspect the replacement. Our showcase preserves failed and revised review notes in `research/`.

See [SONG_INTAKE.md](SONG_INTAKE.md) for arbitrary supplied songs and local alignment. `npm test` covers real encode/mux, cache reuse/invalidation, source offsets, saved edits, downloads, import, deterministic rendering and stale-review rejection.

## Song plus style prompt

Use the autonomous `create` workflow in [CREATE.md](CREATE.md). The local language model translates the brief into scene direction; word identity and timing are immutable during visual direction. The five generic background vocabularies are moving water, contour terrain, star fields, radiant light and architectural grids. Existing photographic assets get restrained camera movement rather than arbitrary water distortion. Semantic scenes remain separately art-directed. The local review model is Qwen3-VL 4B Instruct, installed from the [official Ollama registry](https://ollama.com/library/qwen3-vl:4b-instruct) under `/Volumes/DATA/AI/Models/Ollama`. Model digest: `ee4b975b58c17ce268cd19d40db35d5edc64603035d2ffc1fee1968eb0947f7b`. It uses the existing loopback Ollama service and no inference API fee.

For a brief requiring new art, the agent running this engine generates images with GPT Image and supplies the resulting direction/assets. This is part of the agent workflow; the local renderer never silently calls another image provider. The standalone CLI does not have access to the Codex built-in image tool, so an unmet photographic brief must remain explicitly incomplete until that agent step supplies its assets.

The explicit Instruct tag avoids the default thinking variant's empty-response failure observed in local testing and reported in the [Ollama issue tracker](https://github.com/ollama/ollama/issues/14798). Visual calls reserve 32k context; scene planning uses bounded batches. Incomplete JSON gets one bounded retry, never a fabricated approval.
